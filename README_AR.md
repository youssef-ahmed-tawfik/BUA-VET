# VET BUA — النسخة الأولية بدون Apps Script

هذه النسخة تستخدم موقعًا ثابتًا على Cloudflare Pages، ولوحة Pages CMS لإضافة المحتوى. ملفات المحتوى تُحفظ في GitHub؛ لا نحتاج قاعدة بيانات خاصة بالموقع أو Apps Script.

## التشغيل لأول مرة

### 1. إنشاء مستودع GitHub

1. أنشئ مستودعًا جديدًا على GitHub. المستودع الخاص مناسب إذا كنت لا تريد أن يرى أحد ملفات المصدر.
2. ارفع **محتويات هذا المجلد** إلى جذر المستودع: `index.html`، و`.pages.yml`، ومجلد `data`، ومجلد `lessons`.
3. لا ترفع ملفات `.gs` أو ملفات النسخة السابقة التي كانت تستخدم Apps Script.

### 2. إعداد لوحة Pages CMS

1. افتح [app.pagescms.org](https://app.pagescms.org) وسجّل الدخول بحساب GitHub.
2. ثبّت تطبيق Pages CMS على المستودع الذي أنشأته وامنحه الوصول إليه.
3. افتح المستودع من Pages CMS. سيقرأ إعداد `.pages.yml` ويعرض مجموعة **المحاضرات**.
4. أضف محاضرة من المجموعة: اختر المادة، اكتب العنوان والترتيب، وارفع ملف HTML إن وجد. أضف رابط PDF من Drive ومصادر وأسئلة حسب الحاجة.
5. لحذف محاضرة أو تعديلها، افتحها من المجموعة واحفظ التغيير.
6. لإعطاء شخص آخر حق الإضافة، أرسل له دعوة كمحرر من Pages CMS. يستطيع المحرر تعديل المحتوى والملفات دون الدخول إلى إعداد المستودع.

### 3. نشر الموقع على Cloudflare Pages

1. افتح Cloudflare Pages وأنشئ مشروعًا جديدًا باستخدام **Connect to Git**.
2. اختر مستودع GitHub نفسه.
3. اختر إعداد موقع ثابت بلا إطار عمل: اترك أمر البناء فارغًا، واجعل مجلد النشر هو جذر المستودع `/`.
4. انشر المشروع وخذ رابط `pages.dev` وشاركه مع الطلاب.
5. عند حفظ محتوى في Pages CMS، يضاف التغيير إلى GitHub. Cloudflare Pages ينشر الإصدار المحدث تلقائيًا من المستودع.

لخطوات الربط الرسمية راجع [إعداد Git integration في Cloudflare Pages](https://developers.cloudflare.com/pages/configuration/git-integration/).

## إضافة المحتوى

- **ملف شرح HTML:** يُرفع من حقل «ملف الشرح HTML» في Pages CMS إلى مجلد `lessons` في المستودع، ويعرضه الموقع داخل صفحة المحاضرة.
- **PDF:** يبقى في Google Drive. انسخ رابط المشاركة إلى حقل PDF، واضبط الوصول على «أي شخص لديه الرابط» حتى يفتحه الطلاب. يعرض الموقع معاينة Drive مع رابط لفتح الملف.
- **الأسئلة:** أضف السؤال والاختيارات ورقم الإجابة الصحيحة من 1 إلى 4، ثم تفسيرًا اختياريًا. تظهر النتيجة للطالب عند ضغط «تحقق من الإجابة».
- **المواد:** المواد السبعة مضمّنة في الصفحة الرئيسية، وتبدأ بيانات المحاضرات فارغة في `data/lectures.json`.

## الدخول للمحررين

إدارة الموقع تتم عبر صفحة Pages CMS، وليس من خلال كلمة مرور ثابتة داخل الموقع. استخدم حساب GitHub للمالك، وأرسل دعوة بريدية للمحررين. لذلك كلمة المرور `youssef123` غير مستخدمة في هذه النسخة.

هذا يحمي لوحة التعديل عبر حسابات المصرح لهم، بينما تبقى صفحات الطلاب عامة كما طلبت. محتوى المحاضرات نفسه سيكون ظاهرًا للزوار.

## هيكل الملفات

```text
vet-bua-pagescms/
├── .pages.yml          # حقول لوحة إدارة Pages CMS
├── index.html          # موقع الطلاب المتجاوب
├── data/
│   └── lectures.json   # بيانات المحاضرات (تبدأ فارغة)
├── lessons/            # ملفات HTML المرفوعة من لوحة الإدارة
├── README_AR.md        # تعليمات التشغيل
└── MVP_SPEC_AR.md      # التصور النهائي وخطة التنفيذ
```

## ملاحظات

- Pages CMS يحفظ المحتوى في GitHub مباشرة؛ [المحتوى يبقى في المستودع](https://pagescms.org/docs/)، بينما Cloudflare Pages ينشر الموقع الثابت من المستودع.
- يمكن رفع ملفات HTML من حقل الملفات مع تحديد الامتداد المسموح. [إعداد الوسائط والرفع](https://pagescms.org/docs/configuration/media/) و[حقل الملفات](https://pagescms.org/docs/configuration/fields/file/).
- Pages CMS هو لوحة خارجية سهلة للمحرر، وليس لوحة مبنية داخل موقع الطلاب. زر «إدارة المحتوى» يفتحها.
- حدود Cloudflare Pages المجانية الحالية تشمل 20,000 ملف بالموقع و25 MiB للملف الواحد؛ راجع [صفحة الحدود الرسمية](https://developers.cloudflare.com/pages/platform/limits/).
- لم يتم ربط المشروع بحساب GitHub أو Cloudflare؛ الربط يحتاج تسجيل الدخول إلى حساباتك واتباع الخطوات أعلاه.
